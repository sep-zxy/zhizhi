# 知枝使用指南

[返回项目首页](../README.md)

## 安装与启动

下载对应平台的安装包并安装。Windows 版本面向 x64；macOS 版本面向 Apple Silicon。

应用启动时自动打开本机 Python 服务与桌面窗口，服务只绑定 loopback 地址。使用 Git 来源时请先安装 Git，并确保 `git --version` 可用。

关闭主窗口会收起到托盘；完全退出请选择托盘菜单中的「退出」。

## 配置模型

1. 在「设置」中打开「模型设置」。
2. 添加服务，选择与接口一致的提供商类型，填写别名、接口地址、模型和密钥。
3. 选择生成模型。需要时检查连接；检查连接会发出真实请求。
4. 在模型设置中选择隐私模式。默认 `strict_local`；远程调用需选择允许远程处理的模式。

密钥可能保存在工作区 `.ahadiff/.env` 或系统全局配置中，取决于保存范围。分享源码或导出资料时，排除密钥文件。

## 导入项目与选择来源

在「项目与提交」中导入本地仓库。明确选择仓库路径，扫描提交历史，再选取需要学习的变化。知识条目中的来源可以回溯到提交、文件与相关片段。

在「设置」中可以查看项目扫描配置，也可以手动前往「项目与提交」立即扫描。

首次使用建议选择一条内容清楚、范围较小的修复或重构，便于核对讲解与实际变化。

## 确认候选

「今日归纳」概览聚合出的知识；「待确认」用于逐项审阅。

先查看候选的聚合理由和来源，再决定确认成知识卡、延后、忽略或归并。模型可能把不同机制混在一起，也可能重复提出已有知识，需由你审阅。

## 学习知识卡

1. 阅读卡片讲解，核对引用的代码和提交证据。
2. 回答理解选择题，查看答案与解析。
3. 回答结果预测题，比较自己的判断与解析。
4. 对看不懂的内容，使用当前上下文中的 AI 速问继续追问。
5. 完成学习，按需要提炼 Wiki 草稿。

已学卡片可以重新阅读，也可以标记为不理解或需要回看。修订卡片会保留旧版学习记录。

模型反馈不是执行代码后的结论。重要行为应在自己的项目中通过实际运行或测试核对。

## 写入 Obsidian

在「设置」中配置已有知识库位置和库内目标目录。先确认路径指向自己的库，再保存设置。

在「知识 Wiki」中阅读并编辑学后草稿，核对标题、概念、解释和来源。确认后，知枝将新建或更新相应笔记。已有条目出现更新或冲突时，先核对再确认。

同一知识点的后续经历可以补充到已有条目中。应用内的草稿与外部 Markdown 笔记都需要备份。

## 探讨与导出

「探讨」用于围绕项目问题追问，将有价值的讨论留为知识候选。

知识卡库提供项目知识卡的 Anki `.apkg` 导出。导出是单向的，Anki 内的复习结果不会自动写回知枝。

「设置 → 导出与数据管理」可进入同步、备份与数据管理。外部云服务必须自行部署并配置；本地使用不需要云账号。

## 工作区与备份

默认桌面工作区位于系统应用数据目录：

- Windows：`%APPDATA%\growth-companion-desktop\workspace`
- macOS：`~/Library/Application Support/growth-companion-desktop/workspace`

其中 `.ahadiff/` 保存本地状态、数据库和工作区配置。品牌更新继续使用历史技术目录名。

可靠的备份方式是退出应用后复制整个工作区，并单独备份 Obsidian 库。若配置了全局模型提供商，另行备份其配置与密钥；不要把这些私人备份公开上传。

需要自定义工作区时，在启动进程前设置 `GROWTH_WORKSPACE`，值为绝对路径。该目录不是你的项目源代码仓库；在应用中另行绑定需要扫描的 Git 仓库。

## 常见问题

### 打不开仓库或读不到提交

检查路径是否为 Git 仓库，Git 是否可用，以及当前进程是否有读取权限。新仓库如果没有提交，先在自己的开发流程中生成提交，再扫描。

### 远程模型请求被拒绝

检查提供商类型、模型名、接口地址、密钥与隐私模式是否一致。先执行连接检查，再进行较大的生成请求。

### 升级后是否需要重新导入数据

当前版本沿用 `growth-companion-desktop` 数据目录与 `.ahadiff` 状态。仍建议升级前退出应用并备份；若曾使用 `GROWTH_WORKSPACE`，升级后继续使用相同路径。

### Wiki 没有出现在 Obsidian 中

检查目标库与库内目录是否正确、草稿是否已确认写入，以及是否存在需要处理的冲突。生成草稿本身不会自动写入外部库。

### 如何判断下载文件对应哪次源码

查看随包下载的 `build-info.json`，其中包含源码提交和 GitHub Actions 运行地址。使用 `SHA256SUMS.txt` 核对安装包哈希。
